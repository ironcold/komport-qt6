New findings:

- **HIGH — duration fails when the injected monotonic clock starts at zero.** A valid clock returning `0` at successful start makes every later clean duration report `0`; damage at zero also fails to freeze the damage instant. Minimal fix: do not use `0` as an unset sentinel. Track whether a damage instant exists with a boolean, or choose `mState == Damaged` to select `mEndNs`; add clean and damaged tests with a clock starting at zero.

- **MEDIUM — reader still accepts non-conformant references and creation times.** `sessionJsonIntegerToQInt64()` explicitly accepts JSON numbers, whereas the v1 writer profile requires canonical decimal strings: [helper](/home/max/Development/misc/komport-qt6/komport/sessionevent.h:156). Minimal fix: implement a local reader-only canonical-string validator (`QString::number(parsed) == input`) and reject non-strings, signs, leading zeroes, and whitespace; validate `created` as a valid ISO-8601 UTC value. Add negative mutations for both.

- **MEDIUM — zero-record finalisation omits the mandated status.** SPEC-M9 requires “no session data recorded” ([spec](/home/max/Development/misc/komport-qt6/docs/specs/SPEC-M9-live-session-recording.md:183)), but clean `stop()` assigns an empty reason: [sessionrecorder.cpp](/home/max/Development/misc/komport-qt6/komport/sessionrecorder.cpp:358). The existing zero-record test does not assert it: [test](/home/max/Development/misc/komport-qt6/tests/tst_sessionrecorder.cpp:332). Minimal fix: set that report reason for a clean zero-record recording, adjust the report-field comment, and assert the exact message.
