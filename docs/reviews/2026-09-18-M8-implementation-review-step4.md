### Section compliance

- §6.1: controller is passive and converts all transport signal categories; it does not expose the specified `eventObserved` API.
- §6.2: destruction order is correct. `mSerial` is declared before the `unique_ptr`, and explicit reset in the destructor body is redundant but not contradictory. The controller keeps no transport pointer, so Qt’s automatic disconnection prevents stale delivery after controller destruction. `newDocument()` does not recreate it. The serial-descriptor requirement is unimplemented.
- §7 and §9: normal Live/Idle handling, close filtering, and source-ID filtering mostly work. Failed-open identity handling does not.
- §8: source ID 1, sequences, raw payload copies, and raw source timestamps are implemented correctly for conforming observations. No decoded-data or write path is introduced.
- §10: normal transport observations use one FIFO and the RX→TX two-subscriber test is present. The anomaly diagnostic is the exception and violates the “every event type” rule.
- ADR-005: anchoring, non-reanchoring, `max()` normalization, raw-time preservation, and finite anomaly production are otherwise implemented correctly.
- ADR-003 / ADR-009: no transport ownership or write API was added. The header itself is QtCore-only by inspection; the static assertion does not prove that fact.

### Existing visible behaviour

I found no wiring to existing terminal, hex, logger, configuration, or transmission paths. The new controller observes signals and has no production consumer, so this slice does not appear to change existing visible terminal behaviour. I could not runtime-verify that conclusion.
